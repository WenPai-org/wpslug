# WPSlug 组件拆分与迁移方案（2026-08-09）

> [CX] 1.2.2 只做兼容修复，不拆组件；以下是下一主版本的可选模块建议，不授权自动改写现有 slug、媒体 URL、设置或站点凭据。

## 目标边界

| 组件 | 1.2.2 保持行为 | 下一主版本内部边界 | 可选模块拆分条件 |
|---|---|---|---|
| 拼音核心 | 内置字典，本地同步转换，云失败回退目标 | 定义 `LocalPinyinProvider`，无网络、无凭据、始终可用 | 保持主插件必选核心，不拆成外部依赖 |
| 云翻译 | Google/Baidu 同步请求 | 每个 provider 独立适配器；统一超时、错误对象、fallback 事件；只允许显式预览/保存或队列调用 | 只有在调用量和维护成本有数据支持时才拆可选扩展 |
| WPMind | 通过全局函数探测和调用 | 独立 `WPMindProvider`；固定当前 `wpmind_is_available`、`wpmind_translate`、`wpmind_pinyin` 契约；不可用时回本地拼音 | WPMind 版本兼容需独立发布时再拆扩展，不让主插件硬依赖 WPMind |
| 媒体 normal | `sanitize_file_name` 上转换新上传文件名 | 独立 `MediaFilenamePolicy`；继续只处理新上传并保留扩展名 | 保留主插件可选模块 |
| 媒体 MD5 | 当前是 `md5($name . time())`，不是内容 MD5且不确定 | 标为 legacy，不自动迁移；新 UI 改称“随机匿名文件名”或提供确定性 opaque hash 新模式 | 下一主版本先收集使用量并显示弃用提示；有迁移证据后才考虑移除 legacy 模式 |

## 迁移顺序

1. 先增加 provider/policy 接口和适配器，旧设置键及结果保持不变。
2. 给每种 provider 增加契约测试：成功、超时、非 200、格式错误、不可用和本地 fallback。
3. 增加只读迁移预览，列出将受影响的文章/term；没有显式确认不得写入。
4. 批量迁移使用分批任务、幂等键、前后 slug 记录和回滚清单。
5. 媒体历史记录永不自动重命名；这会破坏附件 URL、缓存和外部引用。
6. 设置升级只迁移 schema，不复制、导出或记录 API 密钥；密钥继续按站点保存。
7. 运行一个小版本的兼容层和弃用日志，再依据实际使用量决定是否拆插件。

## 兼容与验收门槛

- 已有或显式 slug 在普通保存、标题修改、发布状态变化时保持字节级不变。
- provider 失败必须返回本地拼音或原始安全 slug，并记录不含凭据的 provider/fallback 状态。
- 同一批量任务重复执行不产生第二次写入；回滚按记录恢复原 slug。
- 多站点迁移逐站点显式运行，不做 network-wide 默认写入。
- 媒体迁移只作用于新上传；历史附件为零写入。
- 真实 provider 测试需要独立测试凭据，不能用零样本代替通过。


## 无损迁移与回滚契约

- 下一主版本先在主插件内引入 provider/policy 接口，再决定是否交付可选扩展；1.2.2 的选项键、provider 标识和默认行为全部可读。
- 迁移采用 copy-first：旧值校验成功后复制到新 schema，保留旧值至少一个主版本；不移动、清空或记录 API 密钥。
- 可选扩展未安装、未启用或调用失败时，主插件仍以本地拼音完成新内容 slug；已有或显式 slug 始终不重写。
- WPMind 通过能力探测适配，不成为主插件安装依赖；关闭扩展后回到 1.2.2 的本地路径。
- 媒体 normal/legacy MD5 仅处理新上传。历史附件、URL、缓存键和外部引用零写入。
- 回滚到 1.2.2 时继续读取保留的旧键；任何清理旧键的动作必须等待迁移验收和独立发布授权。
